# 一个标签、一行差分

「创立无地头衔」是一个有两页的 Mod 窗口。DS 制作了网页交互和原生 GUI，并用观窗导入原生文件。导入识别出 119 个可编辑目标。这次只把步骤标签 `step_badge` 移近标题，保留原控件、文案表达式和其他 118 个目标。

```diff
- position = { 358 34 }
+ position = { 150 34 }
```

上面是唯一变更行里的位置字段。原始请求定位到 `control7.position_x`，补丁只替换字节区间 `[1136, 1139)`。在同一份基线的散列、节点和旧值都符合时才应用修改。完整导出件经解析器重读，`position_x` 为 150；第二次导入仍识别出 119 个目标，其他字节通过一致性检查。

| 文件 | SHA-256 |
| --- | --- |
| 编辑前原生 GUI | `26d29b64522524c42f4968699e6d8445b9387d5ec9bc91afad88547d7df69146` |
| 完整导出件 | `efc9b3f6231cdcade1e969e4774f5b3081a19dafcaa88068341ebf169809be33` |

![游戏内标题区域，可见向标题移近的步骤标签](images/ds-title.png)

截图取自后续 CK3 1.20.1.2 测试。游戏加载的窗口文件与导出件同哈希，测试副本另有开窗注册和新局入口。图中展示的是修改后的标题区；这次没有留同场景修改前的原生对照，精确改了哪三个字节由补丁证明。

要把方法用到自己的 Mod，先导入原 `.gui`，从 `manifest.json` 选实际控件和可编辑字段，导出后看 `changes.diff`，再把完整文件重新导入。基线变了就重新定位，不把旧文件的字节位置用于新版本。这个案例验证的是已有源码的单属性回写。网页交互和原生玩法各自有独立的验收要求。[源码回写实现](../../source/editing/appearance.py) · [同一窗口的空态验收](empty-state.md) · [研究目录](README.md)
